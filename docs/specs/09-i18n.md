# 09 国际化、多语言与地区适配（I18N）

2026-11-24 新增，规范 v1.1。状态：规划（planned），不是已实现功能。本规范横贯 M2–M5；不改变 M1 已验收的证据、不降低六种 Office 格式及 PDF 的 P0 门槛。M2 开始先建设共用国际化层，三个编辑器不得各自重复实现。M5 首个正式版以本规范定义的 22 个界面 locale 为 P0 目标；未通过则保留开发预览身份，不把语言目录的存在当作支持。

## I18N-02 公共模块、资源、选择及安全（P0）

- 新增 packages/i18n（规划），仅依赖 contracts 或无依赖，提供公开入口、locale registry、类型化 message key、参数 schema、plural/select、格式化及 fallback。desktop/main、preload 的稳定 DTO、ui 共同使用，不形成 DOM/Node 依赖环；core、公式 AST、格式适配器不依赖 UI 语言服务。更新 workspace、架构检查、依赖/许可证清单。
- 目录建议 locales/en-US.json、zh-CN.json 等，英文为规范键基线，简中为第一等语言。另有 meta/registry、术语表、上下文、占位符约束；按 common/shell/writer/sheets/slides/pdf/diagnostics 分 namespace。可采用审计后的 ICU MessageFormat 兼容实现；禁止 eval/new Function、文档执行、模板任意代码和任意 HTML。使用 Intl/ICU 能力需固定环境、验证支持并定义回退。
- 所有用户可见字符串必须通过 t(key,args) 或受控格式化服务：工具栏、菜单、快捷键标签、上下文菜单、对话框、恢复/备份/冲突提示、工作区、PDF、诊断、辅助技术标签、帮助/内置文案、应用控制的安装界面；系统自身对话框/系统术语服从 OS 能力并明确边界。禁止拼接翻译片段替代完整句子；支持参数顺序、复数、长文本、键盘提示。文件名、用户正文、路径、工作表名称、公式字符串不是待翻译资源。
- 诊断跨层传递稳定 code/messageKey、结构化受限参数和 severity；日志只记稳定 ID，不记录私有内容。资源与参数都按纯文本渲染，禁止注入 HTML/链接/脚本；混合方向动态参数使用方向隔离，不把控制符写回用户文件。语言资源只能来自随应用审核打包的本地目录；不得自动下载翻译、远程字体或语言包，不开放 renderer 任意文件路径。
- 首次启动优先系统语言列表，匹配规范化 exact→脚本/语言映射→en-US；简繁按脚本/地区映射（zh-Hans/zh-CN/zh-SG→zh-CN；zh-Hant/zh-TW/zh-HK/zh-MO→zh-TW），pt 选 pt-BR，es 选 es-ES 等；对未支持地区使用同语言默认，否则 en-US。用户显式选择优先于系统；提供“跟随系统”和语言搜索。回退链无环，缺键最后回退 en-US 并记录不含私有内容的诊断；正式版不能靠回退掩盖必需键缺失。
- 现有 settings v1 的 zh-CN 与 en 迁移为显式 zh-CN/en-US，保留主题和最近记录；新 profile 默认 system。版本化、原子持久化、允许回滚；不破坏既有设置或 OEX。界面语言、地区格式 locale（默认 system，可独立修改）、新建文档默认语言三项独立；文档既有语言属性优先，未知语言使用 und 或保留源值，不从 UI locale 猜测。
- 用户切换语言后，renderer 文案、html lang/dir、菜单、应用对话框、辅助技术标签、状态和诊断刷新，无需重启；保留所有标签、选区、滚动、撤销历史、未完成保存、主题。进行中的 IME composition 不得被销毁/重复提交（必要时等当前 composition 结束）。切换 UI/地区偏好不得改变文档源数据、文档 revision/contentId 或 dirty 状态。

## I18N-03 地区格式及 Sheets 公式（P0）

UI/显示层使用显式 locale、时区、日历/数字系统设置及 Intl 的 NumberFormat、DateTimeFormat、Collator、PluralRules 等能力；区分地区格式、用户选择的格式和文档原始格式。支持日期顺序、12/24 小时、小数点、千位分隔符、百分比、货币单位及可配置地区；货币格式变化不是汇率换算。对金额、时间、日期、分隔符歧义提供明确选择或错误，不静默猜测。新建模板可按明确地区偏好选择纸型与计量单位，导入纸型/日期系统/数值/格式码必须保留。

Sheets 的数值、类型、Excel 日期序列/1900 与 1904 规则、公式 AST、计算和格式适配保持确定性，与 UI 语言无关。P0 支持函数集合定义稳定规范函数 ID、区域输入/显示规则和经校验的本地名称别名（没有本地别名的语言保留规范名称）；支持规范英文输入及显式地区输入模式，按目标 Excel 规则处理参数、数字、数组分隔符（超出 P0 的语法明确拒绝/保护），包括小数逗号。不能直接字符串全局替换：引号内文本、工作表名、引用、转义及未知公式保留，按 lexer/AST 处理；避免别名冲突与歧义。DOCX/PPTX/XML 数字与 XLSX/BIFF8 公式序列化使用各自规范表示，未知源式与缓存按既有保护要求保存。通过各地区固定夹具验证数值、引用、错误、公式输入→规范 AST→保存→复开不因语言切换发生改变。UI 搜索排序不得改变文档顺序。

## I18N-04 Unicode、排版、文档语义与 RTL（P0）

- 不限文档文字为 22 个 UI locale；模型/文件 I/O 保留 Unicode 字符、逻辑顺序及源语言标记，语言和书写方向按文档/段落/run/单元格/文本框需要表达。支持混合文字，显式 LTR/RTL/auto、逻辑与视觉位置映射；按 grapheme cluster 移动/删除/选区，处理组合字符、代理对、emoji/ZWJ、印度文字组合。不得对用户文本强制 Unicode 归一化、简繁转换、音译、改变大小写或丢失控制符；比较/索引的规范化与存储分离。
- UI RTL 使用逻辑 CSS 属性（inline-start/end），镜像菜单、导航、对齐和方向性控件；非方向性图标、数字、公式、代码、路径、媒体和实际文档几何不盲目镜像。设置、导航、tab、键盘焦点、原生菜单、弹窗、错误文本和屏幕阅读器均需 RTL 检查。文档与 UI 方向独立；支持 LTR UI 中的 RTL 文档、RTL UI 中的 LTR 文档。
- Writer、Sheets 和 Slides 共享字体度量/形状塑造、bidi、行分割/词边界接口；实现或审计采用通用 Unicode bidi、grapheme、line break 与 shaping 组件（参考 UAX #9/#14/#29），不得引入完整 Office 引擎。覆盖中日韩标点禁则/断行、阿拉伯连写和双向文本、希伯来语、天城文、泰语分词、越南语组合音标；布局、命中测试、选择、光标、打印用同一有效快照。IME 实机提交、取消、撤销、复制粘贴；CJK/印度文字/泰语/RTL 混排回归。当前 M1 Canvas clusterPrecision=estimated 不满足精确排版验收；不得靠删除诊断达标。
- 现代文件保留已理解的 language、bidi、复杂文字和东亚字体等格式属性；旧 DOC/XLS/PPT 按对应规范识别 Unicode/代码页及记录标记，不能用系统 locale 猜测解码，不可表示或未知影响闭包时报告并阻止有损编辑/转换。模型、schema 升级与源数据保护须通过现有 MOD/FMT/LEG 规范验收。
- 字体优先源文件指定字体，缺失时按文字 script、语言、系统可用字体有界回退并显示诊断；支持系统字体和经许可证审查的可再分发字体方案。禁止联网字体加载，禁止未经授权打包或嵌入商业字体。中文简繁、日语、韩语字体按语言区别；字体替换不覆盖源字体标记。记录实际字体、版本、DPI、OS，适用 QA-04；必要时固定开放许可夹具字体。PDF 输出按嵌入许可保留可搜索/选择/复制的 Unicode 文本层和逻辑阅读顺序；不以截图代替文字层，不承诺所有未支持字体/复杂版式无损。

## I18N-05 翻译治理与验收（P0）

- 英文 key schema 是唯一基线；22 个正式 locale 必需键覆盖率 100%，无未知/重复键、占位符及 plural/select 不匹配、未审查机器翻译、意外 fallback。新增功能与对应 locale 更新同提交或明确未完成状态，M5 不允许缺失；单一术语表统一 Writer/Sheets/Slides、撤销/另存/恢复/公式术语。自动生成键类型和覆盖报告，提供贡献语言包说明、版本及审查人记录，机器翻译仅作为候选，不等于质量验收。
- CI 检查 locale registry（22 个目标和方向、系统别名、无环回退）、静态/动态键合法性、所有资源/参数 schema、固定 locale 格式和公式夹具、设置迁移、切换期间模型不变、RTL 逻辑布局。开发伪语言扩展文本约 35%–50%、伪 RTL 以发现截断/重叠；不作为正式语言。
- 三平台真实 Electron 验证每个 locale 的启动、切换、主页及各编辑器关键工作流、设置持久化、菜单/应用对话框与长文本布局。对所有语言进行术语/文案审查和关键界面截图，覆盖默认/最小窗口、浅/深色及高 DPI；自动检查关键控件不重叠、不截断、无缺字/乱码，人工审查记录实际平台和样本。RTL 和 CJK/复杂文字代表夹具做原生 IME、选择、命中、复制粘贴、PDF 搜索和输出；测试记录系统版本、字体、Electron/ICU、locale、样本 SHA、截图、commit，Office 参考验证仍按 QA-03/04。
- 每语言状态 planned/implemented/verified/blocked，分 UI catalog、地区显示、公式输入、文档 script/layout、PDF 五维度；语言支持宣传仅限实际通过范围。所有 P0 语言包、地区/脚本行为、相关六格式及 PDF 验收通过才允许正式发布。新增语言和翻译修正仅执行相关 CI；不为纯规划文档重复原生构建。

## 分阶段实施

| 里程碑 | 工作及退出门槛 |
|---|---|
| M2-I18N（M2 开始时） | I18N-01/02：共用模块、统一 message keys、设置迁移、系统识别、手动热切换、三项独立 locale、伪语言；迁移现有中英文界面，建立 A 批目录和 shell/Writer 相关键。RTL 逻辑布局与字体/Unicode 接口必须从 Writer 开始；不能等 M5 才设计。 |
| M2/M2-L | Writer 语言属性、真实 IME、CJK/RTL/复杂文字布局、DOCX/DOC 源属性与代码页安全保留；A 批已交付功能文案审查与验收。 |
| M3/M3-L | I18N-03：Sheets 地区格式、公式 lexer/AST/别名、XLSX/BIFF8 往返；A 批新增功能翻译，B 批 shell 与已完成工作区语言资源及 RTL 界面接入。 |
| M4/M4-L | Slides 文本框与布局、PPT/PPTX 语言/方向/字体、PDF 文本层与嵌入；A/B 批 22 个 locale 全产品已实现，逐项补齐多语言与跨脚本证据。 |
| M5 | I18N-05：22 个 locale 正式键 100% 通过、质量审查、跨平台与六格式/PDF 多语言回归、发布语言清单；任何未通过 P0 不得发布正式版。 |

不改变自主研发路线；拼写检查、语法检查、自动翻译、OCR、竖排及更复杂版式等额外功能为 P1/P2（既有明确 P0 要求不降级）。这些扩展不得阻塞共用国际化基础，也不得用在线服务绕过离线原则。

# M7 — product stability and deeper compatibility

Baseline public [v0.1.0-dev.3](https://github.com/xzcode/office-ex/releases/tag/v0.1.0-dev.3), exact verified source bf1d87b1301c1a8c4c5d86a5428628f94c89f64e. Continue on m5-distribution-20261125; do not change published tags or master. The current work is incremental post-preview development.

## M7.1 A — XLSX rich text, named styles and chart references

- Admit ordinary rich shared strings and inline strings, with an explicit bounded run model (font family, size, color, bold, italic and underline), without changing scalar formula/clipboard semantics. Cell edits preserve unchanged grapheme-aligned prefix and suffix formatting; inserted text inherits the adjacent preceding run or first run at the start. Cell-level font changes apply to all runs. Copy/fill, clear, undo and native save respect the run model. Virtualized cells render only trusted model spans. Source-owned unchanged shared string nodes and native styles remain preserved; changed runs may materialize resolved theme colors/fonts rather than preserving original theme font tokens. Complex phonetic annotations, unsupported rich font attributes and arbitrary substring formatting tools remain outside this profile.
- Admit a bounded registry of ordinary visible custom named cell styles with direct font/fill/border/number-format components and fully materialized cell formatting. Preserve native xfId association through edits/copies; source style records are retained and new cell XFs appended with mapped original parent IDs. The Ribbon can apply an existing named style or reset to Normal. Source style definition editing, creating new named styles in the UI, named parent alignment and unsupported built-in/complex inheritance remain outside profile. New model fields are validated; legacy XLS conversion rejects unsupported rich/named semantics explicitly.
- Chart range/anchor positions now shift in the same transaction as row or column insertion/deletion. Same-sized local chart vectors remain aligned; destructive source vector or label removal and overflow fail explicitly rather than dropping a chart. New charts are placed below horizontally overlapping charts using existing approximate default grid geometry. Exact floating-object placement and more complex charts remain open.
- Evidence: TypeScript, architecture, 296/296 core tests, targeted XLSX 18/18, desktop build and dependency audit passed. Independent XlsxWriter/openpyxl shared/inline rich text, named association, formula-cache readback and chart range shift passed; added to npm test:interop. Native sandboxed Linux 3/3 [evidence](verification/m7/native-m7-sheets.json): display rich spans, edit retaining unchanged runs, apply named style and save/reopen. Reproduce with `python tests/sheets_m7_interop.py .work/m7-sheet-corpus`, build, and `node --import tsx scripts/smoke-m7-sheets.mjs .work/m7-sheet-corpus`.
- First native test assumed inserted text inherited the title run; corrected the assertion to the specified preceding-space run policy and reran successfully. New exact-source three-platform CI required. No version bump, new release, dependency changes or master merge.

Next proposed M7 focus: remaining practical spreadsheet profiles and chart interoperability; Word first/even running stories and longer margin content; PowerPoint table editing fidelity, then performance, UI regression and release gates. Prioritize real reproducible files and avoid claiming full Office conformance. Formal reference-office, publisher trust, physical IME/print, performance and human locale acceptance remain open.


## M7.2 A — first/even page stories and multiple paragraphs

M7.1 A baseline `b9ef4a49d500402405c2ead0efb45b9df90361e1` passed exact-source [CI 45808092944](https://github.com/xzcode/office-ex/actions/runs/45808092944), including all three native package jobs.

- Model six independent default/first/even header and footer reference slots, section-owned differentFirstPage and document-owned differentEvenOddPages. Effective references inherit the corresponding variant; missing variants remain blank instead of falling back to another kind. PAGE restart/continue selects odd/even variants by actual displayed number, consistent with Microsoft's documented Word implementation in [MS-OI29500 17.10.1](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/e9535962-4cf3-4279-9367-637241e4b195) and [17.10.6](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/bce5f993-d683-4aa7-825e-bce25c64e8b8). First-page override takes precedence. Editing an inherited or multiply referenced variant detaches its native part; toggling flags preserves inactive references.
- Admit up to 16 independent uniformly formatted tab-free paragraphs per story, with one optional decimal PAGE field per paragraph, alignment and verified source-owned stock style. Read/write native titlePg and evenAndOddHeaders; only the understood settings flag is patched, preserving other settings; missing settings receive a collision-free native part/relationship. Unchanged story parts remain byte exact.
- Shared native/estimated page layout projects all admitted story paragraphs in order, preserving vertical gaps for empty paragraphs, and anchors complete footer groups from the bottom. Oversized content is explicitly rejected instead of overlapping body text. The profile still requires each paragraph to fit one line; tabs, mixed runs within a paragraph, drawings, tables, other fields, arbitrary styles, nondecimal numbers and exact Word typography remain outside profile. Legacy DOC serialization rejects unsupported new semantics.
- Layout Ribbon dialog adds page variant, first/even toggles, paragraph selection/add/remove and per-paragraph text, PAGE suffix and alignment. Prevent duplicate context events from discarding in-dialog paragraph edits. All 22 locales have candidate labels, not human-reviewed translations.
- Local 300/300 core tests, 25/25 focused Word pagination/running-story tests, TypeScript, architecture, build and licenses passed. Independent python-docx variant fixture and edited/disabled readback passed: five pages with numbering 4,5,6,10,11, two independent sections, multiple paragraphs, source byte preservation, flags and native PAGE. Added to npm test:interop. Full existing independent Office corpus/readback passed. Sandboxed Linux native 3/3 [report](verification/m7/native-m7-stories.json): five-page projection, real dialog edit/append and DOCX save, real PDF independently extracted with pypdf (test-only) and checked for correct body and running stories. Initial desktop test selected ambiguous option text/value; explicit value selection corrected the test; final run passed. Reproduce using `python tests/writer_m7_stories_interop.py .work/m7-stories-corpus`, build, and `node --import tsx scripts/smoke-m7-stories.mjs` with a Python interpreter containing pypdf configured by OFFICE_EX_PDF_PYTHON.
- Exact new-source CI is required. No new runtime dependencies, version bump, new release, tag change or master merge.

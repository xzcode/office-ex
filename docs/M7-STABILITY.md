## M7.1 A — XLSX rich text, named styles and chart references

- Admit ordinary rich shared strings and inline strings, with an explicit bounded run model (font family, size, color, bold, italic and underline), without changing scalar formula/clipboard semantics. Cell edits preserve unchanged grapheme-aligned prefix and suffix formatting; inserted text inherits the adjacent preceding run or first run at the start. Cell-level font changes apply to all runs. Copy/fill, clear, undo and native save respect the run model. Virtualized cells render only trusted model spans. Source-owned unchanged shared string nodes and native styles remain preserved; changed runs may materialize resolved theme colors/fonts rather than preserving original theme font tokens. Complex phonetic annotations, unsupported rich font attributes and arbitrary substring formatting tools remain outside this profile.
- Admit a bounded registry of ordinary visible custom named cell styles with direct font/fill/border/number-format components and fully materialized cell formatting. Preserve native xfId association through edits/copies; source style records are retained and new cell XFs appended with mapped original parent IDs. The Ribbon can apply an existing named style or reset to Normal. Source style definition editing, creating new named styles in the UI, named parent alignment and unsupported built-in/complex inheritance remain outside profile. New model fields are validated; legacy XLS conversion rejects unsupported rich/named semantics explicitly.
- Chart range/anchor positions now shift in the same transaction as row or column insertion/deletion. Same-sized local chart vectors remain aligned; destructive source vector or label removal and overflow fail explicitly rather than dropping a chart. New charts are placed below horizontally overlapping charts using existing approximate default grid geometry. Exact floating-object placement and more complex charts remain open.
- Evidence: TypeScript, architecture, 296/296 core tests, targeted XLSX 18/18, desktop build and dependency audit passed. Independent XlsxWriter/openpyxl shared/inline rich text, named association, formula-cache readback and chart range shift passed; added to npm test:interop. Native sandboxed Linux 3/3 [evidence](verification/m7/native-m7-sheets.json): display rich spans, edit retaining unchanged runs, apply named style and save/reopen. Reproduce with `python tests/sheets_m7_interop.py .work/m7-sheet-corpus`, build, and `node --import tsx scripts/smoke-m7-sheets.mjs .work/m7-sheet-corpus`.
- First native test assumed inserted text inherited the title run; corrected the assertion to the specified preceding-space run policy and reran successfully. New exact-source three-platform CI required. No version bump, new release, dependency changes or master merge.

Next proposed M7 focus: remaining practical spreadsheet profiles and chart interoperability; Word first/even running stories and longer margin content; PowerPoint table editing fidelity, then performance, UI regression and release gates. Prioritize real reproducible files and avoid claiming full Office conformance. Formal reference-office, publisher trust, physical IME/print, performance and human locale acceptance remain open.


## M7.2 A — first/even page stories and multiple paragraphs

M7.1 A baseline `b9ef4a49d500402405c2ead0efb45b9df90361e1` passed exact-source [CI 45808092944](https://github.com/xzcode/office-ex/actions/runs/45808092944), including all three native package jobs.

- Model six independent default/first/even header and footer reference slots, section-owned differentFirstPage and document-owned differentEvenOddPages. Effective references inherit the corresponding variant; missing variants remain blank instead of falling back to another kind. PAGE restart/continue selects odd/even variants by actual displayed number, consistent with Microsoft's documented Word implementation in [MS-OI29500 17.10.1](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/e9535962-4cf3-4279-9367-637241e4b195) and [17.10.6](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/bce5f993-d683-4aa7-825e-bce25c64e8b8). First-page override takes precedence. Editing an inherited or multiply referenced variant detaches its native part; toggling flags preserves inactive references.
- Admit up to 16 independent uniformly formatted tab-free paragraphs per story, with one optional decimal PAGE field per paragraph, alignment and verified source-owned stock style. Read/write native titlePg and evenAndOddHeaders; only the understood settings flag is patched, preserving other settings; missing settings receive a collision-free native part/relationship. Unchanged story parts remain byte exact.
- Shared native/estimated page layout projects all admitted story paragraphs in order, preserving vertical gaps for empty paragraphs, and anchors complete footer groups from the bottom. Oversized content is explicitly rejected instead of overlapping body text. The profile still requires each paragraph to fit one line; tabs, mixed runs within a paragraph, drawings, tables, other fields, arbitrary styles, nondecimal numbers and exact Word typography remain outside profile. Legacy DOC serialization rejects unsupported new semantics.
- Layout Ribbon dialog adds page variant, first/even toggles, paragraph selection/add/remove and per-paragraph text, PAGE suffix and alignment. Prevent duplicate context events from discarding in-dialog paragraph edits. All 22 locales have candidate labels, not human-reviewed translations.
- Local 300/300 core tests, 25/25 focused Word pagination/running-story tests, TypeScript, architecture, build and licenses passed. Independent python-docx variant fixture and edited/disabled readback passed: five pages with numbering 4,5,6,10,11, two independent sections, multiple paragraphs, source byte preservation, flags and native PAGE. Added to npm test:interop. Full existing independent Office corpus/readback passed. Sandboxed Linux native 3/3 [report](verification/m7/native-m7-stories.json): five-page projection, real dialog edit/append and DOCX save, real PDF independently extracted with pypdf (test-only) and checked for correct body and running stories. ## M7.3 A — native merged PPTX tables and cell formatting

- Native bounded rectangular table grid with rowSpan/gridSpan and hMerge/vMerge continuation validation. Model retains owner text and rejects hidden continuation content, overlapping/invalid rectangles and unsupported continuation formatting. Merge concatenates cell text in row-major order; conflicting explicit formats require reset before merging. Split retains the combined text at the origin. Borders and typography remain approximate compared to reference PowerPoint; complex table styles, mixed run formatting within a cell, diagonal lines, arbitrary continuation formatting, grouped/rotated tables and legacy PPT conversion remain protected. - Desktop table editor has row/column range selection, merge/split, add/delete row/column, color, all-edge border width/color, font/style and alignment controls, reset cell formatting, cancel and one atomic apply with a revision guard. The import/export model supports per-edge borders and margins; UI does not yet expose individual border sides or margin editing. The editor is a modal grid draft, not in-place rich-text editing on the slide canvas. New labels supplied in all 22 locales, subject to human review.

## M7.4 A — sparse calculation, compact history and bounded rendering

M7.3 A baseline `f8f3be70b93b495c508a2fd8fbd6368ee7ee4751` passed [CI 45918606132](https://github.com/xzcode/office-ex/actions/runs/45918606132).

- Spreadsheet sessions coalesce consecutive direct cell patches on the same sheet into one cell-map copy while retaining per-cell forward/inverse patches, validation and atomic undo. Small and medium range commands (up to 4,096 changed entries) use granular cell patches; larger operations retain the existing bounded full-map fallback. Formatting preserves unchanged cell identities and precomputes its shared font patch.
- Sparse formula indexes now include column-ordered entries, so whole-column and single-column range traversal avoids unrelated populated rows. Multi-column row scanning charges the calculation budget even when no matching cells are found. Evaluation order and dependency/step/depth/cancellation limits remain intact. 
- Worker transport projects scalar cell values and sheet identities only. After an acknowledged full request, same-workbook revisions send just added/changed/deleted scalar cells; formatting-only changes send an empty value delta. The worker checks the base revision and workbook identity, retains unchanged sheet map references, and clears its base after a failure. Structural sheet changes and worker restart use a full value projection. The returned formula results are still a full result map. Renderer delta construction still scans changed cell maps.
- Word body pagination reuses immutable body blocks across header/footer or page-number-only edits. Numbering marker invalidation is scoped to each section, and frozen paragraph grapheme costs are cached. Running stories still recompute with the final page numbers; global layout budgets remain enforced.
- Slides retain thumbnail shells keyed by slide ID, preserve rail scroll, focus and unchanged visible scene nodes, and discard offscreen preview content. Only modified visible slide sources or globally affected theme/style/resource/size previews are rebuilt. Thumbnail caching is scoped to a mounted workspace and cleared on disposal.
- Same-host targeted benchmark (Node v24.21.0, Xeon E5-26xx v4; 20,000 data rows and 200 whole-column formulas, five measured runs after warmup): median cold calculation 403.19 → 85.34 ms; format 100 cells and undo 703.22 → 195.99 ms; retained history 2,060,957 → 21,173 bytes. See [before](verification/m7/performance-before.json), [after](verification/m7/performance-after.json), and `node --import tsx scripts/benchmark-m7-performance.mjs`. These are targeted synthetic results, not general end-to-end performance claims or timing gates.
- Final local 308/308 core tests, 42/42 focused regression tests, TypeScript, architecture, build and dependency audit passed. Independent M7 XLSX, DOCX and PPTX interoperability readback passed. Sandboxed Linux native **3/3** [report](verification/m7/native-performance.json): actual worker full/delta/zero-value-delta requests, undo/redo, single-slide edit redraws exactly one visible thumbnail, 60-slide deck retains four visible/nearby preview scenes initially and after scrolling to the end. First native run passed the UI assertions but could not write the report; corrected ownership of the dedicated output directory and reran successfully.

## M7.6 A — bounded source-preserving editing across DOCX, XLSX and PPTX

- Full semantic adapters remain the first choice. When a modern source falls outside the full editable profile, a separately admitted, explicitly limited compatibility editor can modify existing, identified text or scalar slots. The ordinary read-only preview and diagnostic remain available. This is not a projection of the original page, slide or workbook layout.
- DOCX: edit direct text nodes of admitted ordinary body/table paragraphs, preserving bookmarks, direct formatting, page properties, pictures and bounded embedded XLSX packages. Embedded objects are inert; never execute OLE. Raster previews are verified by their actual PNG/JPEG bytes, allowing safe producer mismatches between a PNG declaration and actual JPEG encoding. All untouched package parts and the original image metadata are preserved. Unsupported protected/hidden/tracked/field content and unknown active graphs remain guarded.
- XLSX: existing visible constant cells in formula-free, dependency-free admitted workbooks, with unchanged scalar types, ordinary inline strings or uniquely referenced simple shared strings. Preserve diagonal borders and unsupported style definitions, hidden rows/columns/sheets and unrelated package data. Formulas anywhere (including hidden sheets), chart/drawing dependencies, data validation, filters, protected sheets, ambiguous shared strings and merged-sheet cells remain outside the initial fallback editing profile. Full editor continues to support its existing formula and chart profiles. No stale formula caches are intentionally produced.
- PPTX: existing direct text runs in ordinary top-level text shapes and native table cells, including mixed run formatting. Retain layouts, masters, images, chart/diagram parts and other unedited objects. Complex groups, hidden slides and unsupported wrapped text remain outside the editable slot set. No general canvas editing or slide layout fidelity claim.
- All three adapters use a source digest and bounded edit envelope, not renderer-supplied XML. The main-owned sandbox verifier rebuilds the native output from the authorized import baseline. It verifies output topology, unchanged unrelated part bytes and reversal of the requested scalar/text changes. Existing file authority, backups, atomic save and duplicate-window policy remain in force. Renderer offers explicit opt-in, bounded undo/redo, save/save-as and close confirmation. Compatibility mode has no automatic crash recovery, no structural insertion/deletion, no formatting controls or PDF layout export; the notice discloses this.

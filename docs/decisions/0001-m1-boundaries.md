# ADR 0001：M1 的格式组合、内部草稿与执行边界

- 日期：2026-11-24
- 状态：已采用，原生验证结果单独记录
- 关联：ARC-01/02/03、MOD-01/03/04/05、FMT-01/02/03/05、LEG-01、FS-01/02/03、SEC-01/02/03
- 规范影响：补充实现边界，不删除或降低 v1.0 的六格式和正式版验收要求

## 背景

M1 要交付可运行的桌面基础设施、事务、容器、安全文件流程和恢复，而六种 Office 格式的领域语义适配分属 M2–M4 及旧格式子阶段。需要一种真实可保存、可复开、可恢复的 M1 测试对象，同时避免把容器检测或局部预览描述成 Office 编辑能力。

## 决定一：由 format-service 组合适配能力

新增 `packages/format-service`，作为应用侧的格式组合层。它依赖 `contracts/core/format-common/ooxml/cfb`，提供内容识别、结构检查、能力报告和内部草稿序列化。低层 ZIP/XML/OPC 与 CFB 保持独立；`format-common` 只承载共同契约和有界读取，不反向导入具体容器。

UI 运行时只能从 `format-worker.ts` 导入该组合层；其他 UI 文件只可引用其类型。Electron main 不导入文档解析器。架构检查同时验证公共入口、声明依赖和无环关系。

这补充了规范中的规划模块表。它不会形成第二份文档模型，也不会让格式实现渗入事务核心。将来六个语义适配器仍必须输出同一套 Writer／Sheets／Slides 模型。

## 决定二：使用显式 `.oex` 内部草稿

内部草稿采用有版本的 UTF-8 JSON 包络：

```json
{
  "magic": "office-ex-draft",
  "version": 1,
  "document": { "schemaVersion": 1 }
}
```

这里的 `document` 仅示意包络层；实际文件必须包含通过 `validateDocument` 的完整领域模型。未知包络字段、未知版本、非法模型和超过 32 MiB 的草稿被拒绝。当前尚未封装资源字节，资源集合非空时拒绝草稿保存／导入。

草稿用于验证三种会话模型、命令、历史、保存票据、原子写入、恢复和桌面交互。保存对话框和提交边界要求 `.oex`，不得伪装成 Office 扩展名。源 Office 文件保持结构检查模式；未编辑原样另存复制完整源字节。

`.oex` 不是六格式替代品，也不增加首个正式版的兼容性承诺。DOC/DOCX、XLS/XLSX、PPT/PPTX 的原格式编辑保存和双向转换仍须按原规范实现。格式适配器不存在时保存计划阻止语义导出，不通过扩展名或空白文档回退。

## 决定三：采用 sandboxed renderer 的专用 Web Worker

使用 Chromium Web Worker 运行容器解析、结构检查、草稿序列化和恢复模型校验。该代码不依赖 Node/Electron；同一 worker 实现在 macOS、Windows 和 Linux 运行。`nodeIntegrationInWorker` 关闭，worker 没有主进程文件能力、通用 IPC、shell 或默认网络访问。

主进程只负责用户授权的本地字节 I/O、token 和身份检查、保存提交、私有恢复包络／摘要以及原生交互。文档语义解析不在 main 中执行。可信本地协议只提供明确的应用资源，CSP 和请求策略拒绝外部内容。

每个任务独占 worker，完成、取消或超时后终止；关闭标签同时取消其任务。单任务预算 **15 秒**，最多 **4 个并发 worker**，最多 **32 个文档标签**。超时返回 `limit`；取消返回 `cancelled`。异步派生结果通过任务和 revision 校验，保存中的后续编辑继续保持 dirty。

15 秒是初始运行保护，不是规范中的性能目标达成证据。它不会把超时文件保存为部分结果。worker 隔离与限额也不代替各原生平台的实际 sandbox 验证。

## 决定四：按实际数据执行资源预算

容器 API 可以收紧预算，不能自行提高规范默认值。

| 对象 | 当前限制 |
|---|---|
| 原始文件 | 100 MiB |
| ZIP | 10,000 项；64 MiB／项；累计 512 MiB；压缩比 200:1 |
| XML | 32 MiB／部件；深度 128；1,000,000 节点 |
| CFB | 10,000 目录项；深度 128；64 MiB／流；累计物化 512 MiB |
| 内部草稿 | 32 MiB，完整 schema 校验 |
| 命令历史 | 默认 200 项、64 MiB，保存增量正反补丁 |
| 资源元数据／资源存储 | 默认累计 128 MiB；不会自动清理未知引用 |
| 恢复 | 脏内容每 30 秒检查；最近 3 份；每文档 256 MiB 总预算 |

这些是具体实现的产品限制。真实 DOC/XLS/PPT 记录、公式、图像解码等后续适配器还必须执行各自的规范预算。M1 不能把尚未建立的语义解析和解码路径视为已经安全验证。

## 决定五：Canvas 字簇位置注明估算精度

`render` 保持纯平台无关的几何和 `FontMetrics` 接口；`ui` 提供 Chromium Canvas 适配。整体文字测量和绘制使用同一字体设置、同一 context；UTF-16 位置按 grapheme 边界处理，视觉方向与逻辑位置分离。

Canvas 不公开完整 shaping 字簇／caret 信息。当前适配器根据前缀宽度计算字簇区间，并明确返回 `clusterPrecision: "estimated"` 和对应诊断。该信息可验证 M1 渲染接口和坐标通路；混合 bidi、复杂字形连接、精确选区、换行、分页和 Office 字体一致性不得据此宣称完成。

M2 可以引入经审查的通用文字 shaping／字体度量组件或扩展本机接口，保持同一接口和字体环境标识。精度升级需真实文本、字体、DPI 和参考结果的证据，不能删除 `estimated` 标记来通过验收。

## 保存保证的实际边界

文件 token 绑定窗口、会话和操作；保存采用同目录临时文件、内容重读验证、文件同步、最后身份复核、原子提交和替换前持久备份。新目标采用不会覆盖意外出现文件的提交方式。

Node 缺少可移植的目录句柄相对操作和“仅当 inode 未变才 rename”原语。实现重复检查父目录、源身份和临时文件，并保留旧版本，但无法排除最后检查与 rename 之间由其他进程发起的竞态。返回的 durability 区分完整目录同步和仅文件同步；受限文件系统不会被描述成拥有相同保证。

这项工程边界必须保留在 M1 说明和后续安全验收中。未来如引入原生文件层，应以具体平台测试改善保证，不能通过修改规范或隐藏诊断消除问题。

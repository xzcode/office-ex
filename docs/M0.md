# M0 — 技术决策与构建基线（2026-11-24）

## ADR-001：引擎选型

状态：首选方案确定，构建和兼容性验证尚未通过。

- ONLYOFFICE Desktop Editors：现有原生桌面容器、OOXML 编辑逻辑及 PDF，优先复用。保留 C++/Qt、桌面 SDK 与 Web 编辑器架构，不再增加 Electron 包装层。
- LibreOffice：成熟的 ODF/OOXML 编辑器，备用方案；独立测试时用其作为交叉读取参考，不代表 Microsoft Office 或 ONLYOFFICE 的表现。
- Univer：核心组件适合 Web 应用，但完整文档交换、演示及高级模块的授权与功能覆盖需逐项验证；不作为当前桌面主引擎。
- 自研 OOXML 引擎：不采用。成本与文档损坏风险不可接受。

锁定桌面 v10.0.0（上游发布于 2026-10-13），具体源码提交及六个 Git 子模块来自该 tag。build_tools 无同名 tag，单独记录查询时 master 的 SHA，不能宣称已形成完整可复现构建。上游 web-apps-pro 为 web-apps 的历史名称，保留实际 gitlink 与规范仓库 URL。后续需要锁定全部递归依赖、下载校验值、编译器、Qt、CEF、字体及工具链。

## ADR-002：应用边界

Office EX 桌面壳负责起始页、本地文件入口、标签页、设置、主题、备份与错误处理；desktop-apps/desktop-sdk 提供桌面窗口和桥接；sdkjs 负责编辑模型，web-apps 负责编辑 UI；core 负责文档转换等底层工作。直接使用 upstream 桌面架构，不引入服务端、账号或默认 AI/云功能。UI 中文/英文，默认本地处理。宏执行、外部内容、网络访问需独立安全策略。未知格式不能静默丢弃内容。

## 构建顺序

1. Ubuntu 24.04 amd64 上游构建基线：官方建议 4 CPU、8 GB RAM、4 GB swap、100 GB SSD。使用独立工作目录或专用构建机，禁止在有其他项目的目录里执行上游自动化。先运行 preflight，明确磁盘及联网许可。
2. 按 lock.json 检出 DesktopEditors 与六个子模块。独立检出 build_tools 提交，审查 configure.py、make.py 与依赖脚本，记录缺少的兄弟仓库、下载源和版本。完整构建锁定前不输出 Release。
3. 上游说明的 Linux 探索性构建：在独立 build_tools checkout 的 tools/linux 中执行 python3 ./automate.py desktop --branch=master。该命令会下载依赖、安装系统包并更新/切换源码；仅允许在专用构建环境中人工发起。它使用移动分支，**不是** v10.0.0 的锁定构建。要验证 v10.0.0，必须准备匹配源码布局和完整依赖后使用 configure.py 的 --update 0 路径，并确认整个构建未重新拉取未经锁定的代码。不要直接照搬 master 命令来声称 v10.0.0 已构建。
4. Linux 成功后，在原生 macOS ARM64（Apple Silicon，Xcode/Qt/CEF 原生工具链）验证源码编译、签名和安装；Windows x64 使用原生 Windows 工具链。上游存在这些平台发行包，不等于已验证我们能复现。Linux 不冒充 macOS 原生打包环境。无需在 M0 创建 Release。
5. 保存精确源码/工具链版本、构建日志、退出码、产物 SHA256 和启动记录。首个可安装衍生版本前完成版权清单和源码提供方式。

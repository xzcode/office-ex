# M0-R2 — independent Office EX architecture (2026-11-24)

## Decision

The user explicitly selected independent editors with only supporting generic libraries. This supersedes the earlier ONLYOFFICE plan (97941ff). No upstream office editor source was imported; remove the previous upstream lock and build scripts from the active tree. Preserve Git history and original synthetic interoperability fixtures. Root license remains MIT.

## Architecture

- Desktop: Electron + TypeScript, independent UI and original icons. Electron provides the platform window, web renderer, system dialogs and printing primitives, not an office editor. Renderer sandbox/context isolation; no Node integration; local-only custom protocol, scoped preload IPC; explicit permission and network policy.
- Core model (shared TypeScript): immutable document state or transactions, typed commands, selection, undo/redo, clipboard semantics, autosave and recovery. Independent of DOM and Electron.
- Writer: original paragraph/run/table/section/page models; font measurement, line breaking and pagination, cursor/selection and IME, document editing and print layout. Canvas/DOM and platform text primitives are infrastructure, not imported editor logic.
- Sheets: sparse cells, virtualized viewport, types, ranges, style model, references, formula lexer/parser/AST, dependency graph, recalculation, cycle/errors. No eval of user formulas; external links and macros disabled. Formula export is not formula evaluation.
- Slides: original scene/shape/text/image model, page thumbnails, z-order, geometry, transforms, guides and rendering; presentation mode.
- Format layer: own OOXML part and relationship mapping, adapters and diagnostics; generic XML and bounded ZIP libraries. Keep original unknown parts and relationships where safe; do not silently save unsupported features. Atomic Save As and preserve original. PDF reading/export is planned, no PDF editor dependency selected.
- UI: shared desktop shell, tabs, menus/toolbars, light/dark, English/Chinese, keyboard shortcuts, recent files. macOS ARM64 first; Windows/Linux supported after native validation.

## Dependencies

Node 22.13+ and TypeScript 5.8.3 tested in M0. Candidate runtime components: Electron (MIT plus bundled notices), fflate (MIT ZIP), @xmldom/xmldom (MIT XML). No runtime dependency installed yet; select exact current safe versions and lock hashes after network access. Python ZIP and python-docx/openpyxl/python-pptx are test-only. No full editor, formula engine or layout engine reused.

## Compatibility strategy

Start with OOXML transitional DOCX, XLSX and PPTX. Prioritize new-file creation, common feature import/edit/save and preservation of unmodified parts. Unknown unsupported features trigger warning or read-only mode. Never claim 100% fidelity. Legacy binary Office and ODF are later phases; no macro execution. XML parsing must reject DTD/external entities, constrain depth/size, ZIP extraction must enforce entry/count/decompressed limits, canonicalize paths and reject traversal; do not follow external relationships or load remote assets automatically. Preserve existing files and verify changes against independent readers and native Microsoft Office.

## M0 implementation

packages/ooxml/src/export.ts contains original minimal Writer and Sheets part writers. Handles document text/bold, line breaks/tabs, Unicode/XML escaping, multi-sheet strings/numbers and explicitly typed formula serialization, basic sheet/cell validation. Python test harness packages actual OOXML ZIPs and independently reads them. No import, pagination, real formula evaluation, chart, UI, or PPTX export yet. Node package has no third-party runtime dependency.
